# Learning Arcade カードシリーズ追加

## 概要

このスキルは、このリポジトリに新しいカードガチャシリーズを追加するときに使う。テーマ企画、カード案作成、画像生成、アセット保存、`cardCatalog.ts` 登録、ガチャ画面とカードずかんの確認までを一連の作業として扱う。

作業前に、リポジトリの `AGENTS.md` に従って次のドキュメントを読む。

- `docs/repository-architecture.md`
- `docs/soroban-practice-mode-spec.md`
- `docs/soroban-test-mode-spec.md`
- `docs/soroban-game-mode-spec.md`

カード定義と画像生成の細かいルールは `references/card-series-guide.md` を読む。

## 作業手順

1. 既存カードの作りを確認する。
   - `src/features/soroban/cardCatalog.ts` を読む。
   - ガチャ種類ボタンの数が増える場合は `src/features/soroban/views/GachaPage.tsx` も確認する。
   - `src/assets/cards/*` の既存ファイル名を確認し、IDやファイル名の重複を避ける。
   - カード画像を作る前に、既存カード画像をサンプルとして必ず読み込む。`src/assets/cards/` から代表的なカードを2〜3枚選び、画像ビューアや利用可能な画像確認ツールで実際に見て、構図、枠、質感、色使い、けいまるくんの表情を把握する。
   - 画像生成プロンプトは、読み込んだサンプルの観察結果に合わせて調整する。既存カードを見ずに新規カード画像を生成しない。

2. 画像生成前にシリーズを企画する。
   - `gachaId`、日本語のシリーズ名、短い表示名、シリーズ説明を決める。
   - ユーザー指定がなければ、1シリーズあたり5枚作る。
   - 既存シリーズと被らない、まとまりのあるテーマにする。
   - `references/card-series-guide.md` のけいまるくんの基本プロファイルと好み・苦手なものを参照する。
   - 各カードについて、場面、ポーズ、小物、表情、カード上の見出し、ファイル名、カードID、カード名、説明文案を決める。

3. ユーザー意図に応じて確認または実行する。
   - ユーザーが明確に「作って」「追加して」と依頼している場合は進める。
   - テーマ、枚数、雰囲気が曖昧な場合は、短い企画案を出して承認を取ってから画像生成する。

4. カード画像を生成する。
   - ビットマップ画像生成には `imagegen` スキルまたは画像生成ツールを使う。
   - 通常は縦向きのコレクションカード構図にする。
   - 縦向きカードは既存の標準サイズ `1024x1536`、横向きカードは `1536x1024` を目安に、同じシリーズ内の画像サイズを必ず揃える。
   - サイズが揃わない場合は、単純な画像処理で無理に伸縮・クロップするより、サイズ指定を強めて再生成することを優先する。
   - 既存カードの雰囲気に合わせる必要がある場合だけ、画像内に日本語タイトルを入れる。
   - カード下部に「けいまるくん」の名前プレートや表記は入れない。必要な名前は `cardCatalog.ts` の `name` で管理する。
   - 既存カードの単なる焼き直しは避ける。
   - けいまるくんらしさは維持する。ぬいぐるみ風、たれ耳、ふわふわ質感、少しむすっとしたかわいい表情、カラフルなカード枠を基本にする。

5. 画像アセットを保存する。
   - 完成画像は `src/assets/cards/` に置く。
   - ファイル名は小文字の kebab-case にし、末尾は `-card.png` にする。
   - 例: `keimarukun-night-pool-card.png`
   - 生成画像が汎用名やUUID名の場合は、コード登録前に分かりやすい名前へリネームする。
   - 保存前に `file` などで画像サイズを確認し、同じシリーズ内で寸法が揃っていることを確認する。

6. `cardCatalog.ts` に登録する。
   - 各画像を import する。
   - `CardGachaId` に新しい `gachaId` を追加する。
   - `CARD_GACHA_DEFINITIONS` にシリーズ定義を追加する。
   - `KEIMARUKUN_CARDS` に各カードを追加する。
   - 横向き画像だけ `orientation: "landscape"` を付ける。
   - `addedOn` は、ユーザー指定がなければ現在のローカル日付にする。

7. ガチャ画面の収まりを確認する。
   - カードガチャの種類ボタンは `GachaPage.tsx` で10件ごとにページングする。
   - シリーズを追加してページが増える場合は、別ページに `NEW` 対象があるとページ送り矢印にも `NEW` が出ることを維持する。
   - ボタン群やページ送りを広げた場合は、右側のラインナップ表示と被らないよう `left` や幅を調整する。
   - カード追加に必要な範囲だけ変更し、大きな画面 redesign はしない。

8. 検証する。
   - `npm run build` を実行する。
   - ユーザーから明示依頼がない限り `npm run dev` は起動しない。
   - 最後に、変更ファイル、生成アセット、検証結果を簡潔に報告する。

## 説明文の書き方

カード説明文は、既存の子ども向け文体に合わせる。

- ひらがな多めにする。
- 短く、具体的に書く。
- 絵に見えている行動、表情、小物を説明する。
- 文末は原則 `けいまるくん。` にする。
- 絵に見えない設定や抽象的なほめ言葉は避ける。

例:

- `おもいぼーるをかかえて ぷるぷるふるえる けいまるくん。`
- `どんじゃらであがって とくいげに はいをみせる けいまるくん。`
- `おにくはのーさんきゅーで やさいとばななをやく けいまるくん。`

## 守ること

- 新しい localStorage キーを増やさない。
- 問題生成ロジックを変更しない。
- カード追加だけならルートを変更しない。
- 画像がない場合に落ちない既存の fallback を壊さない。
- 関係ないリファクタリングをしない。
